- **T381** — **Conservative-grounding indexing contract** — pinned and documented the absent-vs-empty rule for `TurSNJobItem.attributes`: an absent field is a missing key (never `null`/`""`/empty collection), and the indexing boundary (`TurSNProcessQueue.getConsolidateResults` / `removeDuplicateTerms`, via the shared `isGroundedValue` predicate) drops `null`, blank-string, and empty-collection values so they are never materialized as an empty value in Solr/ES — keeping facet counts and `exists`-negation filters correct. - **T409** — **Lucene DSL executor: type-aware numeric/currency range + sort** — fixed two correctness bugs in `TurDslLuceneExecutor` that T407 surfaced. Numeric/currency/date fields are indexed as Lucene `*Point` + `NumericDocValues` (never string terms), but the executor translated every `range` as a lexicographic `TermRangeQuery` (matched **nothing** on those fields) and every `sort` as a `SortedSetSortField` (**threw** on numeric doc-values → the whole query returned empty). Sorting is also **fail-open**: an unsortable field degrades to relevance order instead of dropping the result set. The interface entry points (`translateQuery`/`translateSort`) keep the string-fallback behavior, so Solr/ES executors and existing callers/tests are untouched. This makes numeric/currency range filtering and sorting actually work for catalogs on the embedded Lucene engine (the cursarei/T385 NL→facet path). Covered by `TurDslLuceneExecutorTest` (deterministic translation unit test) + the now-green T407 IT.
